## 1. Arquitetura Atual de i18n

### Middleware (`src/middleware.ts`)
- Redireciona `/` → `/{locale}` baseado no cookie `NEXT_LOCALE` ou default `pt`
- Ignora: `/admin`, `/api`, `/_next`, `/media`, ficheiros estáticos
- 5 locales configurados: `pt`, `en`, `es`, `it`, `de`

### Dicionários (`src/i18n/dictionaries.ts`)
- ~100 chaves traduzidas para 5 idiomas
- Função `getDictionary(locale)` com fallback para `pt`
- Abrange: navegação, carrinho, checkout, cupões, atributos de produto, estados, 404, erro, loading

### Layout com html lang dinâmico
- `[locale]/layout.tsx` é root layout do frontend
- `<html lang={locale}>` dinâmico (pt, en, es, it, de)
- Locale validado contra Set dos 5 idiomas; inválido → `notFound()`
- Payload Admin tem root layout independente

## 3. Limitações conhecidas

- `html lang` em páginas 404: Next.js usa `<html id="__next_error__">` sem lang (limitação do framework)
- Loading global do produto: removido para preservar HTTP 404 real
- html lang dinâmico: concluído para páginas frontend válidas
- Payload Admin: isolado, intacto, usa `<html lang="en">` (comportamento do Payload)
- Sem push até autorização final

## 4. Códigos de erro de cupão

```ts
type CouponErrorCode =
  | 'INVALID_COUPON'  → dict.invalidCoupon
  | 'EXPIRED'         → dict.expired
  | 'MIN_ORDER'       → dict.minOrder
  | 'FIRST_ORDER_ONLY' → dict.firstOrderOnly
  | 'SOLD_OUT'        → dict.soldOut
  | 'INCOMPLETE_DATA' → dict.incompleteData
  | 'NO_CODE'         → dict.noCode
```

Mapeamento tipado em `src/lib/coupon.ts` com `CouponErrorDictKey` (7 literais).
Frontend prefere `error_code` → dicionário, fallback `error` string, fallback `dict.orderError`.
